Scala 3 · self-hosted · zero JVM

Scala 3, compiled straight
to native. No JVM. Ever.

scalino builds and runs Scala 3 straight to a native executable via Scala Native — no bytecode, no JIT, no java anywhere on the machine. The compiler, linker, and LSP server are themselves self-hosted: compiled by dotc from their own patched source, targeting Scala Native directly.

Install

One line. No JVM to set up first.

Grabs the latest release for your OS/arch, verifies its checksum, and installs scalino to ~/.local/bin. The only thing it expects already on the machine is clang — every build links through it, even a zero-dependency Hello World. Packages (deb, rpm, Arch, Nix, Homebrew) install bash/zsh/fish completions for you.

shellscalino install
# installs to ~/.local/bin, verified checksum
curl -fsSL https://raw.githubusercontent.com/lolgab/scalino/main/install.sh | bash
curl -fsSLO https://github.com/lolgab/scalino/releases/download/vX.Y.Z/scalino_X.Y.Z_amd64.deb
sudo apt install ./scalino_X.Y.Z_amd64.deb
# clang is wired in as a real package dependency
sudo dnf install https://github.com/lolgab/scalino/releases/download/vX.Y.Z/scalino-X.Y.Z-1.x86_64.rpm
# installs to /usr/lib/scalino/, symlinked into /usr/bin/
# each release ships a self-contained dist/ tarball:
# compiler + linker + scalino, for linux/macOS (x86_64+arm64)
./dist/scalino
# shell completions: dist/completions/, or `scalino completions <bash|zsh|fish>`

Scalino in action

Shaped like scala-cli, on purpose.

Same //> using directives and flags as scala-cli — dep, -w, -o — so existing muscle memory carries straight over.

scalaHello.scala
object Hello:
  def main(args: Array[String]): Unit = println("hello from scalino")
$ scalino — run is the default command, no build step to think about
import scala.quoted.*

object Foo {
  inline def myMacro(): Unit = ${ aMacroImplementation }
  def aMacroImplementation(using Quotes): Expr[Unit] = '{ println("Hello") }
}
$ scalino run — expanded by scalino's own from-scratch TASTy tree interpreter, not JVM bytecode execution
//> using dep com.github.plokhotnyuk.jsoniter-scala::jsoniter-scala-core::2.40.1
//> using compileOnly.dep com.github.plokhotnyuk.jsoniter-scala::jsoniter-scala-macros::2.40.1

import com.github.plokhotnyuk.jsoniter_scala.macros.*
import com.github.plokhotnyuk.jsoniter_scala.core.*

case class User(name: String, devices: Seq[Int])
given codec: JsonValueCodec[User] = JsonCodecMaker.make
Resolution shells out to a bundled, renamed coursier (scalino-cs) — no separate install, classpaths cached in .scalino-build/.
scalino run -w
Rebuilds and reruns on save, with scala-cli-style output (same wording, colors and diagnostics). Builds are incremental: only changed sources recompile. Same flags as scala-cli: --dep, -S/--scala, -O/--scalac-option, --main-class, -o/--output. Boolean flags like -w work before the sub-command, and every command has --help.
//> using test.dep org.scalameta::munit::1.0.0

scalino test .
scalino test . --test-only "*MySuite*"
Finds munit, utest, scalatest and zio-test automatically. --test-only <glob> links only the selected test classes, so the rest never reach the binary.
scalino package -o hello
./hello
A real, standalone native executable — no JVM, no bytecode, nothing to install on the machine that runs it. Tune it with --native-mode release-fast, --native-gc, --native-lto, or shrink it with --native-prune (link-time method pruning).
scalino package app/ -o myapp \
  --native-target-triple x86_64-unknown-linux-musl,aarch64-unknown-linux-musl
# -> myapp-x86_64-unknown-linux-musl, myapp-aarch64-unknown-linux-musl
One command, several platforms, one linker process — the program is parsed once. Missing sysroots are assembled on first use. Musl targets are fully static, so one binary runs on every distro.
scalino package . --format tar,deb,rpm,docker -o packages --pkg-version 1.2.3
scalino package . --format brew --release-url https://github.com/me/app/releases/download/v1.2.3
No fpm or dpkg needed. Metadata comes from //> using packageName|packageVersion|packageDescription|… directives.
scalino setup-ide
Generates .scalino-build/scalino-lsp.json, then scalino-lsp gives your editor diagnostics, completions, hover, go-to-definition, references, and rename — without Metals' JVM dependency. Zed and VS Code offer to run it for you in a project that hasn't been set up.

Benefits

Why scalino, not scala-cli + a JVM.

0

Zero JVM, top to bottom

Compiler, linker, build tool, and LSP all ship as native executables. Nothing you run day to day touches java.

⚡

Fast to install, fast to run

One native binary — no JDK to provision, no setup-java step. Starts instantly, no JIT warmup, which adds up over every CI run.

⚙

Fast builds

Object files come straight from libLLVM's C API — no .ll text, no per-file clang. Compilation and linking are both incremental, so a rebuild touches only what changed.

▫

Lean binaries

4-byte object headers (class id and lock bits in one word) shrink every object and array, on by default. Escape analysis moves short-lived objects to the stack, and --native-prune drops unreachable methods at link time.

#

Hermetic builds

scalino lock pins every jar by URL and sha256, and --offline builds with no network. A Nix flake builds on top of it.

→

Cross-compile from anywhere

Build for Linux (musl and glibc), macOS and Windows from one machine with --native-target-triple. Sysroots are assembled client-side from pinned upstream packages.

▣

Ship it packaged

scalino package --format emits tar, deb, rpm, docker and Homebrew artifacts — no extra packaging tools.

$

Familiar by design

A mini scala-cli, shaped like the real one on purpose — same directives, same flags, same instinct for finding your entry point.

Cross-compile & package

Build once, ship everywhere.

Pass one or more target triples and scalino links them all in a single linker process. A sysroot holds each target's libc headers and libraries; scalino sysroot build <triple> assembles one on your machine from upstream packages, each checked against a pinned sha256 — it needs only curl and tar, nothing is compiled. scalino package builds missing ones for you.

shelltargets
scalino package app/ -o myapp --format tar,deb \
  --native-target-triple x86_64-unknown-linux-musl,aarch64-apple-darwin

# linux musl / gnu (glibc >= 2.31), macOS, Windows (mingw, experimental)
# x86_64 and aarch64 — from any host
//> using nativeTargetTriple … works too. run and test always build for the host. Cross targets need lld (on a Mac, macOS targets need nothing extra); the Windows sysroot needs clang 21 or newer.

Hermetic builds

Lock it, then build with no network.

Nix builds can't reach the network, so dependencies need a lockfile that something else fetches first. scalino lock writes one; --offline (or SCALINO_OFFLINE=1) builds from it and the local cache only.

shell / nixscalino.lock.json
scalino lock .          # per jar: path + URL + sha256
scalino run . --offline # lock + local cache only

# flake.nix
scalino.lib.${system}.mkScalinoApp {
  pname = "myapp";
  src = ./.;   # contains scalino.lock.json
}
Every locked jar is fetched with pkgs.fetchurl. mkScalinoDevShell gives an offline nix develop shell where scalino-lsp and go-to-definition into libraries work too. Linux and macOS, x86_64 and aarch64.

Editor support

Metals-inspired tooling, without Metals' JVM.

scalino-lsp is built on dotc's presentation compiler and self-hosted the same way as the compiler. It covers diagnostics, completion, hover, go-to-definition (into dependency sources read straight from their jars, and into Scala Native's own sources), type definition, references, rename, selection ranges, inlay hints, semantic tokens and code actions. It shuts down when idle, keeps its memory footprint low (evacuating GC, heap that shrinks back to the OS), lets you toggle inlay hint kinds from editor settings, and Neovim clients reattach on restart.
